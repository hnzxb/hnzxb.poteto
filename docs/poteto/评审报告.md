## 3. 系统性缺口清单（按"能在哪一层强制"上移排序）

**缺口 A：评审输出的结构契约没有机器强制 → 应上移到第 2/3 层**

→ 上移到：lint 自定义规则或测试断言（校验输出含五个 section 标题、含"事实采集边界"节）。

**缺口 B：`test:self` 单文件 = 验证体系空壳 → 应上移到第 3 层**
`gate` 只跑一个测试文件，等于"门禁存在但门很窄"。评审工具的核心行为（给定事实 → 产出五件套、拒绝臆测、事实不足如实标注）没有任何测试覆盖的证据。
→ 上移到：为评审输出加行为测试（fixture 输入 → 断言输出结构），并把测试分层（回归层进默认入口）。

**缺口 C：poteto 工具箱未部署 → 第 3 层工具缺失**
方法论知识库自己不用 pstack，等于"教人搭灶台自己吃外卖"。
→ 部署 `/create-verification-skill` 为本仓库生成确定性验证 CLI + feature map。

**缺口 D：prose 层过重 → 应尽量上移**
`skills/` + `AGENTS.md` + README 原则三重叠加，存在规则重复表述风险（同一原则在多处措辞不同 → Agent 会挑最省事的那条抄）。
→ 上移到：把可机检的规则抽成 lint/测试，prose 只留判断类。

**缺口 E：`.env` 未被忽略 → 第 2 层止血**
探针 `env被忽略: false`。这是确定性、零成本、必须立刻补的 lint/配置层缺口。
→ 上移到：`.gitignore` 加 `.env*`（这属于第 2 层"确定性止血"，不是 prose 建议）。
