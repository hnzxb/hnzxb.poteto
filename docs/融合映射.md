# Poteto 方法论 ↔ 本机 CLAUDE.md 融合映射

目的：把信任倒金字塔落到本机既有规范上，标注已覆盖项、部分覆盖项与空缺项，指导后续 skill/脚本的演进。配套技能：`../skills/poteto-verify/`、`../skills/poteto-correct/`。

## 逐层对照

| 金字塔层级 | poteto 实践 | 本机对应 | 覆盖度 |
|---|---|---|---|
| 1. 代码库与架构 | 结构上消除坏写法、强类型不变量、代码库即记忆 | KeepModules 方法论、`@keepdb/kit` 原子工具复用、Schema 契约校验（ArkType/JSON Schema）、Surgical Changes | ✅ 高度一致 |
| 2. 静态分析 | Lint/类型/CI 确定性止血 | `just check` 静态门禁前置、ESLint、CI 部署门禁（GitHub Actions） | ✅ 已覆盖 |
| 3. 验证体系 | 确定性 CLI + feature map、验证光谱、autopilot fuzz | proof-gate skill、变更验证铁律；**缺项目级 feature map 与确定性验证命令沉淀** | ⚠️ 部分 → `poteto-verify` 补齐 |
| 4. Prose 规则 | 用得越少越好、禁止过时注释 | rules/*.md 收敛、"注释即例外"、记忆原则（只记非显性事实） | ✅ 高度一致；纠错上移机制 → `poteto-correct` 补齐 |
| 5. 人工审查 | 抽样 + 模式发现，缺口上移 | proof-gate 一页纸 Proof 报告替代逐行 review | ✅ 已覆盖 |

## poteto 值得引入但本机暂缺的实践（按优先级）

1. **确定性验证 CLI 沉淀**（已建 `poteto-verify`）：验证命令收敛到 justfile / package.json，禁止会话现写脚本。
2. **Feature Map**（已建 `poteto-verify`）：项目 `docs/功能地图.md`，功能↔到达路径↔验证命令。
3. **纠错台账**（已建 `poteto-correct`）：错误类别↔规则↔执行者对照，持续把 prose 挪进代码。
4. **过夜循环 / autopilot**：依赖 harness 的后台循环与 fuzz 验证；本机可用 `/loop` + proof-gate 组合近似，暂不建独立 skill。
5. **内外环自动化**（Slack/Sentry 触发 triage）：依赖外部系统接入，暂缓；树莓派面板（pi-panel）可作为首个试点外环。
6. **多模型对抗评审（arena/interrogate）**：pstack 原生能力，装 pstack 插件即得，不自建。

## 明确不采纳

- 小任务跑全套流程（pstack 社区实测 token/时间倒挂）——与奥卡姆剃刀冲突。
- TLA+ 形式化验证作为默认层——仅测试触达不了的竞态/状态机场景个案引入。
- 大量剧本（playbooks）复制——本机 dev-flow 已覆盖开工/收工/快速三态，按需从 pstack 单独引用剧本即可。

## 使用方式

`skills/` 目录为可移植技能源：需要时复制 `skills/poteto-verify/`、`skills/poteto-correct/` 到目标项目 `.claude/skills/` 下即可被 Claude Code 识别。技能文档遵循 Agent Skills 格式（SKILL.md + YAML frontmatter）。
