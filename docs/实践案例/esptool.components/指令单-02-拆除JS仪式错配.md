# 指令单 02 — 拆除 JS 仪式错配（技术栈对齐 ESP-IDF 生态）

**产出方**：hnzxb.poteto 旁路专家 ｜ **执行方**：esptool.components 开发 Agent ｜ 2026-11-23

## 1. 修改目标与问题证据

专家在建设期给一个 **ESP-IDF C 组件库**装了整套 JS 仪式：`package.json`、`bun.lock`、`node_modules`、vitest、`bin/comp.js`、`tests/cli.test.js`。这些对 C 组件零治理覆盖——vitest 测的是目录遍历脚本，不是任何组件；违反金字塔第 1 层"布局须符合生态惯例，反惯例是隐性认知税"。目标：JS 仪式归档拆除，验证入口回归 ESP-IDF 原生。

## 2. 影响范围与禁改范围

- 归档至 `archive/2026-11-23-js-仪式/`（用户全局规则：禁直接 rm）：`bin/`、`tests/cli.test.js`、`package.json`、`bun.lock`、`node_modules`（node_modules 可直接删，非源码）
- 同步修订 `docs/规划/组件标准化约定.md` 中 npm 范式/CLI 相关条款：版本真源回到 `idf_component.yml`，package.json 生成机制整段移除（归档备注留索引）
- **禁改**：`docs/规划/` 其余文件、`components/` 骨架、`docs/poteto/`（工具箱文档不含 JS 依赖，保留）
- `tests/poteto/check.js` 是纯 node 文件存在性自检，无 npm 依赖，保留（若不愿留 node 依赖，可改为纯 shell，执行方自定）

## 3. 预期产出形态

仓库根不再有 package.json/bun.lock/node_modules/bin；约定文档无 npm 段落；归档目录含被拆文件与一行说明。

## 4. 验证命令

```bash
git status --porcelain        # 仅归档新增 + 约定文档修改
ls package.json bun.lock 2>&1 # 应报不存在
grep -c "npm\|package.json" docs/规划/组件标准化约定.md  # 应为 0
```

## 5. 通过标准

- 四个 JS 仪式产物全部归档或删除，仓库树对 C 工程干净
- 约定文档无残留 npm/CLI 引用（含交叉引用）
- 首个验证入口留待消费工程接入时以 `idf.py build` 建立（本单不做）
