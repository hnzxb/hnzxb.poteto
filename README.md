# hnzxb.poteto — Poteto 方法论旁路专家

基于 Lauren Tan（@poteto）**信任倒金字塔**方法论构建的旁路专家（sidecar expert）知识库。给它任意一个项目，它会基于本仓库沉淀的方法论、技能与实践案例，对该项目进行专业评审，并按授权边界产出改进。

## 核心理念

**一切归结于信任（Trust）**：高质量产出不靠盯单个 Agent 微操，而靠设计一个让 Agent 默认做对的环境。评审一个项目，就是评审它的信任阶梯搭到了哪一层。

信任倒金字塔（投入优先级从高到低）：

1. **代码库与架构** — 结构上消除坏写法，让"容易的事 = 正确的事"；布局须符合生态惯例，反惯例是隐性认知税
2. **静态分析** — Lint / 类型 / CI，确定性、低成本止血
3. **验证体系** — 给 Agent 手和眼：确定性验证命令 + 功能地图；测试分层归位，默认入口只含回归层
4. **Prose 规则** — 自然语言约束，能不用就不用
5. **人工审查** — 仅用于发现系统性缺口，发现后立即上移

## 工作方式（三段式，按授权递进）

1. **只读评审**（默认）：逐层判定 ✅⚠️❌ + 证据路径，输出报告五件套——总评、覆盖度表、系统性缺口（上移优先排序）、可执行改进项、明确不建议项
2. **授权实施**：用户显式授权后直接落地（个人工具/纯增量/合规自测可自行裁决），每步带可运行验证证据；业务代码改动仍需单项授权
3. **指令单制**：目标项目有专属 Agent 时，产出 diff 级实施指令单，由对方执行，专家按退出码与证据验收

**合规自测知行合一**：专家自己出的门禁标准，必须在自己触达的项目里以 `tests/poteto/` 先红后绿自证（红旗快照记入案例 CSV），不许只指手画脚。

**角色边界**：产出是目标项目的自我规范能力，不是代工。抱怨/情绪化表达不构成授权，拿不准就反问。
