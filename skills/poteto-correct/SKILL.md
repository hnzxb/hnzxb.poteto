# Poteto Correct（纠错上移）

核心思想来自 poteto 信任倒金字塔：**纠正 Agent 错误时，优先投到更高层**——成本更低、更确定、更持久。每纠正一次都要问："能不能往上挪一层？"

## 执行流程

1. **收集失败模式**：回顾本会话/近期会话中反复出现的纠正（同一类而非同一个），归类成错误类别清单。单次失误不进本流程。
2. **逐类上移**，按层级从高到低找第一个能强制执行的落点：

   | 层级 | 落点示例 | 融合的本机规范 |
   |---|---|---|
   | 1. 架构与代码库 | 重构消除坏模式、清晰模块边界、API 形状、强类型不变量（ArkType / JSON Schema 契约） | KeepModules 规范、Schema 契约优先 |
   | 2. 静态分析 | ESLint 规则、tsconfig 严格化、CI 门禁、justfile recipe | `just check` 静态门禁前置 |
   | 3. 验证体系 | 项目 verify skill / 功能地图加验证行 | [[poteto-verify]]、proof-gate |
   | 4. Prose | CLAUDE.md / AGENTS.md / rules/*.md 补一条规则 | 最后手段，一条规则一个事实 |
   | 5. 人工审查 | 仅用于发现系统性缺口，发现后立即上移 | —— |

3. **写入对照表**：在项目 `docs/纠错台账.md` 追加：

   ```markdown
   | 错误类别 | 规则 | 执行者（层） | 落点 |
   |---|---|---|---|
   | 忘记归档直接 rm | 删除必走 archive/ | 4. Prose + 1. 工具 | ~/.claude/CLAUDE.md 文件删除防护 |
   ```

   已有更高层执行者的条目不再靠 prose 提醒——prose 规则能删就删（注释同理：poteto 视过时注释为有害范本）。

4. **清旧债**：规则上移后，让 Agent 顺带清理代码库里该错误类别的存量（lint --fix、批量重构），保持"被抄也没关系"的园丁状态。

## 判断标准

- 规则若 Agent 违反后 lint/类型/测试会红 → 已有执行者，不写 prose。
- 只有无法机械化的判断（业务约束、审美偏好）才留在 prose，且写清"为什么"。
- 每轮纠错后更新台账，规则与执行者配对不上的条目视为债务。

## 禁止

- 一出错就往 CLAUDE.md 堆规则（prose 膨胀 = 判断负担转嫁给 Agent）。
- 为单次失误建规则。
- 直接删除旧规则/旧脚本：走 `archive/{yyyy-mm-dd}/` 归档。
